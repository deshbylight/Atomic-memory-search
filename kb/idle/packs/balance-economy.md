# balance-economy

## prestige reset mechanics
- [model] Layered prestige stacks resets where each layer clears everything beneath it and adds a new currency and optimization problem, such as an Ascension layer followed by an Eternity layer. When: when a single reset loop would exhaust the optimization puzzle over very long play. Why: Each new layer changes what the player solves, keeping a finite curve from feeling finished.
- [model] Each prestige upgrade has four properties: the stat it affects, a bonus per level, a maximum level, and a first-level cost in prestige currency. When: Designing permanent prestige upgrades. Why: These fields define how fast and how far each upgrade scales.
- [definition] A voluntary prestige reset clears most current progress in exchange for prestige currency or a permanent multiplier; also called rebirth, ascension or reincarnation. When: Designing a meta-progression loop; when a run's progression curve has flattened. Why: Resetting trades visible progress for a faster next climb; turns repeated runs into faster, stronger cycles.
- [definition] Prestige resets grant a currency and a multiplier; their main jobs are the ladder-climbing feeling and keeping numbers in a manageable range.
- [mechanism] Multipliers triggered at generator count thresholds cause bursts of rapid purchases as the player reaches each threshold. When: Designing multipliers unlocked at generator milestones. Why: Players rush to reach the threshold.
- [mechanism] Output comes from owned units plus stacked multipliers: milestone bonuses triggered when 25, 50, and 100 units are owned, one-time upgrades, and prestige multipliers. When: when layering production boosts in an idle game. Why: Stacked multipliers compound with unit count, letting output keep pace with geometric cost.
- [mechanism] A meta-currency earned only by resetting is usually scaled to a measure of the run being given up, such as lifetime earnings. When: when designing the currency a prestige reset grants. Why: Scaling to the run given up rewards the sacrifice and makes each reset worth doing.
- [mechanism] Meta-currency granted by resetting adds permanent production bonuses that persist across runs and speed up each later run. When: when a prestige reset grants a persistent currency. Why: Permanent bonuses make each new run climb faster than the last.
- [mechanism] With a prestige exponent of 0.5, doubling currency requires four times the total XP, so short early resets are worth more than one long run. When: Choosing the exponent of prestige currency. Why: Diminishing returns reward multiple shorter cycles over a single long run.
- [mechanism] A stat's bonus multiplier starts at 1.0 and adds bonus-per-level times purchased level for each matching upgrade. When: Several prestige upgrades affect the same stat. Why: Additive stacking keeps each upgrade's contribution predictable.
- [mechanism] A square-root prestige curve gives large early bonus jumps and diminishing gains later, creating a difficulty curve without explicit level design. When: when later resets should matter but be harder to justify. Why: the square root slows growth as points rise.
- [behavior] Players learn to want prestige resets when the reset is framed as a fast-forward rather than a loss. When: when presenting a prestige reset to players. Why: Framing the reset as acceleration turns a sacrifice into a desired step.
- [behavior] A prestige reset asks the player to give up visible progress for permanent power, and the trade feels worthwhile when the next run is faster, opens new upgrade routes, or shifts bottlenecks. When: when the player weighs whether to reset. Why: the permanent gain must outweigh the visible progress lost.
- [rule] Make the next run noticeably faster within the first 30 seconds after a prestige reset; otherwise the reset reads as pure loss or punishment and players stop resetting. When: when designing prestige rewards. Why: Players need a visible faster recovery to justify giving up progress; otherwise the prestige system fails.
- [rule] A prestige reset clears resources and upgrades but keeps its permanent bonuses.
- [rule] Anything representing player skill and knowledge persists through prestige, while anything representing in-game resources resets. When: Deciding what a prestige reset keeps or clears. Why: Keeping skill and knowledge preserves meaning, while resetting resources keeps the loop worthwhile.
- [rule] Add deeper prestige layers only when the earlier layer already feels rewarding and clear, and each layer stays understandable to the player.
- [heuristic] Vary multiplier values per generator to produce shifting purchase priorities over time. When: Designing generator progression. Why: Changing relative value keeps player choices from becoming fixed.
- [heuristic] Vary reset timing like the rest of the run, with slow and fast stretches, arising from multipliers, upgrades, prestige-currency gain, and player reset choices. When: Designing prestige loop pacing. Why: Uniform reset timing feels monotonous.
- [heuristic] A dungeon run can award meta currency from floors cleared (since-reset) or deepest floor reached (max-based), and the choice determines whether replaying shallow floors stays rewarding. When: Designing dungeon meta progression. Why: Measure choice sets reward for repetition versus progression.
- [heuristic] A simple cost growth factor alone does not give relief; a dense layer of targeted multipliers is what lets production catch up with rising costs. When: when a geometric cost curve starts outpacing income. Why: Targeted boosts jump production at key moments, which closes the gap that cost growth opens.
- [heuristic] Award one prestige token per fixed number of lifetime resources earned. When: A simple prestige currency is needed. Why: A flat rate is easy to explain and predict.
- [heuristic] Offer a prestige reset when progress meaningfully slows, so the reset feels like a fresh start with a real advantage. When: Deciding when to offer a prestige reset. Why: A reset is only attractive when the current run has stalled.
- [procedure] 1) Divide current points by 1000. 2) Take the square root. 3) Round down to an integer bonus. 4) Set the permanent multiplier to 1 plus bonus times 0.1.
- [procedure] 1) Run a periodic global tick about every 60 seconds. 2) Show the prestige prompt only if the preview gives at least 3 tokens and the current run has lasted at least 1800 seconds. When: Deciding when to surface the prestige prompt. Why: Thresholds prevent prompts that offer too little or appear too early.
- [metric] Prestige currency equals the floor of lifetime earnings raised to an exponent of 0.5 to 0.8, times a multiplier. When: Calculating prestige currency from lifetime progress. Why: Exponents below 1 give diminishing returns so repeated resets stay worthwhile.
- [tradeoff] Resetting early yields a small permanent reward, while waiting too long lets temporary progress stall; reset timing is itself a strategic choice.
- [tradeoff] Too much carry-over makes a prestige reset feel meaningless, while too little makes it feel punishing. When: Choosing what a prestige reset keeps. Why: Carry-over sets how much a reset feels like progress versus loss.
- [pitfall] A preview below 1 token means no token is available, so the prestige prompt should not appear. When: Checking whether a prestige reset would yield any currency. Why: Showing a prompt with zero reward is confusing.
- [pitfall] Stacking prestige layers without changing the underlying problem each time only makes the numbers bigger, not the game fresher. When: when adding prestige layers to an idle game. Why: Larger numbers alone give no new decisions, so players stop caring about the extra layer.
- [fact] Most prestige formulas use fractional exponents such as square or cube roots, not true logarithms, so currency can still grow very large.

## idle game economy
- [model] An economy needs faucets (currency sources) and sinks (spending places), or currency accumulates until it becomes meaningless. When: Designing an idle game economy. Why: Currency without spending opportunities stops mattering to players.
- [model] A resource economy has four kinds: primary resources are abundant and used broadly; secondary resources need processing; tertiary resources are rare and gate progression; currency is a universal exchange. When: Designing the resource structure of a game. Why: Each tier plays a different role in creating choices and pacing.
- [definition] A primary exchange currency converts one resource into another, adding a layer that lets designers adjust the exchange rate over time.
- [mechanism] Each manually purchased tier 1 building boosts all tier 1 production by 0.05 percent, keeping manual purchases valuable even with billions of free units. When: Lower tiers are produced for free by higher tiers. Why: A per-purchase boost gives manual purchases lasting value.
- [mechanism] Resources with two uses create decisions such as processing versus selling, or spending now versus saving for a later use. When: Each resource has at least two uses. Why: Competing uses force players to choose how to allocate scarce output.
- [rule] Use each dungeon's unique reward in at least one crafting recipe or give it a meaningful stat bonus; otherwise it loses relevance after its first clear. When: Designing dungeon reward items. Why: Players have no further use for an unused reward once obtained.
- [rule] Give every resource at least two distinct uses, such as fuel, crafting input, or sale for currency; a single use leaves players no real choice. When: Designing or reviewing resources in an economy. Why: A single use gives players no real choice.
- [rule] Give every content tier at least one meaningful currency sink. When: Designing currency sinks across tiers. Why: Sinks in each tier keep currency meaningful as income grows.
- [rule] Use direct purchase for items that skip a crafting step, but price them high enough that crafting stays relevant. When: Selling crafted-equivalent items in a shop. Why: Cheap shortcuts make crafting pointless.
- [heuristic] Price a tier 1 item so it seems attainable at tier 1 and nearly free by tier 3, letting players feel their growing economic power. When: Balancing prices across tiers. Why: Shifting affordability across tiers makes progression feel like growing power.
- [heuristic] Price bulk consumables by tier so higher-tier food costs more per unit than lower-tier food. When: Designing shop consumables across tiers. Why: Tiered pricing matches the value of stronger consumables.
- [metric] Price / income by tier, gold: T1 (levels 1–14) 50–200 / 10–50 per hr; T2 (15–29) 500–2,000 / 200–500; T3 (30–49) 5,000–20,000 / 2,000–8,000; T4 (50–69) 50,000–200,000 / 20,000–80,000. When: Setting prices and income for an idle RPG with four tiers. Why: Matching prices to income keeps purchases meaningful at each tier.
- [metric] Set shop prices near thirty to sixty minutes of farming earnings, scaled to each item's tier. When: Pricing shop items in an idle game. Why: This keeps items attainable within a session while still requiring saving.
- [metric] Cooked food heals in combat by tier: tier 1 gives 3 HP, tier 2 gives 5 HP, tier 3 gives 10 HP, tier 4 gives 14 HP, tier 5 gives 20 HP. When: Setting healing values for cooked food. Why: Rising healing per tier rewards higher-level cooking.
- [metric] Gathering yield multiplier is 1.00 below mastery 25, up to +3% at mastery 25 to 49, up to +7% at mastery 50 to 98, and 1.10 at mastery 99. When: Applying mastery yield bonus to gathering.
- [pitfall] Lower tiers can become irrelevant to buy because higher tiers already grow them for free. When: Designing a derivative chain without tier interaction. Why: Automated production removes the need to purchase lower tiers.

## prestige measurement and simulation
- [mechanism] With lifetime or max-based prestige, doubling prestige currency requires earning several times the previous run, so players must keep progressing. When: Designing lifetime or max-based prestige formulas. Why: Currency is tied to cumulative past performance.
- [mechanism] With since-reset prestige, resetting at the same point repeatedly yields the same currency, so replaying the same point stays rewarding. When: Designing since-reset prestige formulas. Why: Currency is independent of previous runs.
- [behavior] Full offline earnings make active play feel pointless, so offline rewards should keep being present better than being absent. When: Setting offline reward rate. Why: Equal offline reward removes incentive to play actively.
- [rule] Use structural fixes for stalls: a prestige reset, a fresh system that alters the optimization problem, limited-time events with temporary boosts, or social features giving outside reasons to return. When: A progression wall or clicker fatigue needs fixing. Why: These change the structure of play rather than simply slowing progress.
- [rule] Hidden formulas may drive the simulation, but visible consequences should drive player decisions.
- [heuristic] When progression hits a wall, introduce a fresh decision instead of extending the waiting time. When: Progress stalls at a wall in an idle game. Why: A new choice changes the optimization problem, while longer waits only extend the stall.
- [heuristic] When designing allocation choices, ask what resource currently caps growth, and whether short-term output is worth a long-term cost. When: Evaluating idle production choices.
- [procedure] 1) Build a simple single-generator spreadsheet. 2) Vary parameters within reasonable ranges. 3) Plot generators owned over time, where each drop to zero marks a reset. 4) Check the spread of reset timing. When: Balancing a prestige loop or modeling prestige behavior. Why: Sweeping parameters reveals how the loop behaves across likely player choices and captures most players, though individual reset behavior is hard to predict.
- [procedure] 1) Plot the progression curve over time. 2) Find the points where time-to-next-purchase spikes. 3) Treat each spike as a churn cliff and add a structural cure there. When: Diagnosing where an idle game loses players. Why: Spikes in waiting time mark the points where players are most likely to quit.
- [tradeoff] Lifetime or max-based formulas reward continued progression, while since-reset formulas reward replaying the same point but yield diminishing returns beyond a point if the curve is flat. When: Choosing a prestige currency measure. Why: The measure determines whether progress or repetition is rewarded.
- [pitfall] Treating a simulation's output as an accurate prediction of player behavior is a mistake; use it as a rough guide. When: Interpreting balance simulation results. Why: Players deviate from modeled reset behavior.
- [pitfall] Under a flat since-reset curve, ideal strategy may involve little progress beyond a certain point, so such systems need very different balancing. When: Using flat since-reset prestige curves. Why: Returns flatten, making further progress unrewarding.
- [pitfall] A stall with no layer, event, or reset beyond it turns into an exit instead of a difficulty spike. When: A stall has no reset, layer or event beyond it. Why: Players see no future payoff, so the wall simply drives them away.
- [fact] Prestige currency can be computed from max earnings, lifetime earnings, earnings since last reset, or upgrades bought since last reset.
