## K01-21

**Different activities can use different time budgets.** Exploration, travel and extended projects can advance different clocks.

- Kind: general guidance. Focus: moment session and long-term loops; simulation time.
- Apply: Record which clock each activity advances.
- Limit: Tabletop periods are not digital timing targets.
- Check: Trace one action at each scale and its costs.
- Requires [K01-04](Foundations.md#k01-04): The approved time contract prevails.
- Supports [K04-04](EconomyAndProgression.md#k04-04): Recurring actions consume an available budget.

## K01-22

**Unfinished milestones can connect successive visits.** A project can retain completed milestones while later steps require further resources.

- Kind: general guidance. Focus: repeat visits.
- Apply: Record completed and remaining steps.
- Limit: This does not authorize offline progress or training features.
- Check: Return after one funded step; distinguish progress from remaining costs.
- Requires [K01-02](Foundations.md#k01-02): Each step needs defined conditions.
- Supports [K06-04](SpatialDesign.md#k06-04): Retained progress can change a return visit.

## K01-23

**A cycle boundary needs an explicit reset scope.** Recovery rules restore different state under different conditions. By inference, a new period alone cannot specify everything that resets.

- Kind: design inference. Focus: reset and season boundaries.
- Apply: List the trigger, cleared state and retained state for each boundary.
- Limit: This inference does not authorize seasonal resets or changes to world persistence.
- Check: Advance the boundary and justify each changed field by its declared trigger.
- Requires [K01-04](Foundations.md#k01-04): Reset triggers must respect the approved persistence contract.
- Requires [K01-02](Foundations.md#k01-02): A reset needs an explicit state transition.
